## 1. 语言与表达
- 全程使用**简体中文**思考、沟通、编写文档与代码注释（专有名词、代码标识符除外）。
- 结论先行，直接给方案和结果，不说套话、不无端推诿；不确定的地方直接说明，绝不编造文件、接口或测试结果。

## 2. 先定方案，再动大代码
- 涉及多文件修改、新功能架构或复杂重构前，先输出简洁的修改计划与涉及文件清单，等我确认后再动手。
- 局部小改动直接执行，遵循“最小改动原则”，不顺手重写或格式化无关代码。

## 3. 工程与代码规范
- 严格遵循当前项目的目录结构、代码风格、命名规范与既有包管理器/锁文件。
- 未经明确要求，不擅自升级依赖版本、不引入不必要的重型库。

## 4. 安全红线（配合极速模式防翻车）
- 严禁在代码、日志或提交记录中硬编码 API Key、密码等敏感信息。
- 涉及**不可逆或高风险操作**（批量删除文件、覆盖重要数据、`git push --force`、修改系统全局环境变量等），执行前必须先提示并征得同意。

## 5. 验证与交付
- 每次修改完成后，尽量通过本地构建、静态检查或测试验证改动是否生效。
- 汇报时明确列出修改了哪些文件、跑过哪些验证，严格区分“已实测通过”和“未验证”。
